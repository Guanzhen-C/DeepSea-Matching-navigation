# 系统集成与板载部署执行检查表

项目名称：基于迁移学习的海底地形重建与高精度定位技术研究。任务归属：8月平台搭建与9月板载部署。整理日期：2026年10月2日。

## 一 集成边界

仿真环境负责地形、AUV运动、传感器观测、真值及展示；导航端负责惯性与DVL估计、声呐相对匹配、多候选地形定位和全局发布。板载目标运行导航端、地图查询及日志功能，仿真画面无需整体迁入板卡。仿真和实机通过相同数据契约接入，运行链路不依赖真值话题。

当前仓库已提供ROS 2相关传感器发布接口和算法模块，板载独立进程、设备驱动与目标架构依赖仍需按环境核查。已有73 km仿真运行记录只能证明该环境中的链路，不代替实际板卡回放记录。

## 四 数据契约

| 输入 | 必需内容 | 单位及处理 |
| --- | --- | --- |
| IMU | 时间戳、角速度、比力、协方差及坐标系 | rad/s、m/s²；明确比力是否已去重力 |
| DVL | 底跟踪速度、有效束数或质量、协方差、坐标系 | m/s；底跟踪与水跟踪不可混用 |
| 深度 | 压力或换算深度、基准、协方差 | Pa或m；记录换算关系和符号 |
| 测深 | ping编号、各回波时间、束坐标或角度距离、有效标志 | m、rad；保留运动补偿信息 |
| 侧扫 | 同一ping编号、每侧同步行、斜距栅格、强度及有效区 | 保存原始比例和增益，不传显示配色代替数据 |
| 先验图 | 测深、可选强度、投影、垂向基准、有效区和不确定度 | 地图版本和文件哈希固定 |

运行输出包含Local位姿及相对协方差、Global位姿及状态、map→odom、有效候选和时间戳。不存在确认位置时应输出不可确认状态，而不是凭空给出高置信位置。

## 五 依赖与启动检查

逐项检查Python及数值库版本、OpenCV、特征批量后端、GTSAM固定滞后接口、原生3D-BBS库和消息接口。目标架构需要重新构建的扩展明确记录；不要直接拷贝另一架构生成的动态库。可先使用固定记录流验证算法，不强制板卡加载完整仿真运行环境。

运行前检查地图有效航线、输入频率和配置。5 Hz声呐、4个物理ping子帧等设置需与正式基线一致；更换频率、设备模式或数据分辨率后建立新基线。设备不支持2个可区分在水ping时，按真实协议调整发射计划，并重新验证足迹重叠。

## 六 测试与验收检查项

| 检查项 | 执行方法 | 应保存的证据 |
| --- | --- | --- |
| 单位与外参 | 固定姿态、平移和转弯样例校验方向 | 外参表、结果与输入片段 |
| 同源数据 | 检查强度像素对应测深回波 | ping编号、索引和异常计数 |
| 时钟 | 比较采样时间、接收时间与处理时间 | 同步误差、延迟和倒序统计 |
| 状态一致性 | 相同流与参考环境比较 | 位姿差、创新、因子与候选差 |
| 队列与丢帧 | 持续回放并记录队列长度及缺失序号 | 处理耗时、丢帧与输出率 |
| 异常恢复 | 注入无效DVL、空ping、NoData和进程重启 | 回退状态及恢复日志 |
| 连续运行 | 代表性流不少于30 min，后续扩展全程 | 完整记录、退出原因及资源趋势 |
| 可复现交付 | 新环境按说明安装和启动 | 版本、配置、启动命令及文件哈希 |

地图全程误差验收与环境部署验收分别进行。首次板载回放先要求不改变算法输入、无非预期掉帧、输出可对照；精度目标沿用对应数据集已冻结的基线，而不是统一声称所有区域达到同一米级值。

## 七 成果归档模板

实机测试记录应填写：测试日期、负责人、板卡标识、系统版本、算法提交、依赖版本、地图哈希、回放文件、配置文件、输入输出频率、持续时间、异常计数、退出状态与结果附件。未实施时保留为待填写，不写为已完成安装。

部署交付包包含代码或构建产物、依赖说明、默认配置、样例数据、地图来源、启动脚本、运行记录及故障处理说明。阶段成果名称为“地形地貌匹配仿真系统计算平台”和“板载算法部署链路初步贯通”，完成程度以相应测试附件为依据。
